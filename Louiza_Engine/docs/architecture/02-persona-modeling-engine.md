# Layer 2: Persona Modeling Engine (PME)

## Purpose

The Persona Modeling Engine (PME) is responsible for constructing, validating, and maintaining a **finite, versioned set of agent personas** that parameterize behavioral heterogeneity across the Louiza Engine.

Each persona represents a **behavioral archetype**, not a demographic segment. Personas specialize the Individual Behavioral Dynamics Engine (IBDE) via parameters; they do not implement behavior themselves.

PME operates **offline / episodically** and never executes inside the per-timestep simulation loop.

For the POC, PME must work entirely from **synthetic datasets** generated by the Data Engine, using the same contracts that will later support real data.

---

## Non-Goals (Explicit)

PME must **not**:

- Run per-timestep logic
- Modify agent state
- Execute simulations
- Perform anchoring optimization
- Call IBDE or LPM
- Generate numerical forecasts
- Depend on LLMs for clustering or scoring

Any violation is an architectural error (see `99-invariants.md`).

---

## Inputs

PME consumes **snapshot-based, versioned inputs** from the Data Engine and Anchoring Engine.

### Required Inputs (POC)

From synthetic Data Engine outputs:

- `survey_responses`
- `taste_ratings`
- `choice_experiments`
- `features_persona_discovery`
- `observed_metrics_brand_week_region` (via anchoring residuals)

From Anchoring Engine (optional but recommended):
- persona-level residual summaries
- entropy / identifiability metrics

All inputs must reference an explicit `data_version`.

---

## Outputs

PME emits a **versioned PersonaSet**:

- `PersonaSet_vN`
- JSON persona definitions (authoritative contract)
- Population weight priors
- Diagnostics and lineage metadata

Outputs are **immutable once published**.

---

## Persona Lifecycle (POC)

### Phase 0: Seed Persona Initialization

For the POC, PME must initialize with **K seed personas** (recommended K = 8–12):

Examples:
- Price-Sensitive Loyalists
- Promotion-Driven Switchers
- Novelty Seekers
- Convenience-First Regulars
- Brand-A Loyalists
- Brand-B Loyalists

Seed personas may be:
- expert-defined
- coarse clusters over survey features

Once initialized, seed personas are treated identically to learned personas.

---

### Phase 1: Persona Fit Evaluation

For each active persona:

1. Project observed data into persona-conditioned feature space
2. Measure:
   - reconstruction error
   - likelihood / fit score
   - unexplained variance

If all personas explain the data within tolerance → **no change**.

---

### Phase 2: Residual Analysis

If unexplained variance exceeds threshold:

- Identify residual clusters across:
  - region
  - channel
  - time
- Verify:
  - temporal persistence
  - minimum population mass
  - behavioral coherence

Noise-only clusters must be rejected.

---

### Phase 3: Candidate Persona Proposal

A candidate persona may be proposed **only if**:

- residual cluster persists across multiple windows
- variance reduction is statistically meaningful
- candidate parameters differ materially from existing personas

Candidate personas are created in **shadow mode**.

---

### Phase 4: Shadow Evaluation

Shadow personas:

- do not affect live simulations
- are evaluated via historical replay
- must demonstrate:
  - improved fit
  - stability
  - interpretability

Only then may they be promoted to active status.

---

Versioning & Reproducibility

Every PME run produces a new PersonaSet_vN

Persona definitions are immutable once published

All downstream layers must pin to a persona version

Persona diffs must be logged explicitly

Integration With Other Layers
Data Engine

Supplies synthetic surveys, choice experiments, features

IBDE

Consumes persona parameters only

Never queries PME

LPM

Samples agents using persona weights

Persona membership fixed per run

Anchoring

May adjust permitted parameters only

Triggers PME reevaluation if residuals persist

Failure Modes & Guardrails

Reject persona explosion (hard max persona count)

Reject non-persistent residual clusters

Reject unstable shadow personas

Fail loudly on schema violations

One-Line Canonical Summary

PME constructs and governs a stable, versioned set of behavioral archetypes using unsupervised analysis of aggregated data, enabling heterogeneous agent simulation without destabilizing execution.
